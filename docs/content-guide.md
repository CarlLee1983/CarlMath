# 內容撰寫規範

本文件是撰寫 CarlMath 教材的依據，讀者是之後新增單元的站主與 agent。內容涵蓋教材檔與 frontmatter、一般篇與親子共學篇的結構、語氣與用語、數學式寫法、MDX 元件、教具的使用規則，以及「下一步」規則，最後說明內容驗證腳本會自動檢查哪些項目。教具怎麼畫不在本文件範圍，請見 `docs/figure-guide.md`。

條文來自教學研究（`research/pedagogy` 分支的 `docs/research/pedagogy.md`），每條都有代號，例如 CPA-1、RP-4。研究文件替每條標了「實證」或「推論」，本站的採用方式如下：標「實證」的條文是硬性規則，不得違反；標「推論」的條文預設採用，只有在有具體理由時才偏離，並應把理由記錄下來。這個原則有兩處例外：

- **MC-1**（在 metadata 列出常見迷思）不照原文採用。常見迷思寫在正文的「常見迷思」段，frontmatter 不新增欄位。
- **AD-6**（不採用表達性書寫欄位）不列為條文。它在研究文件中只是說明為何排除某種作法，本站本來就沒有這類欄位。

權威順序由高到低是：ADR（`docs/adr/`）、本文件、研究條文原文。本文件與 ADR 衝突時以 ADR 為準，並應回頭修正本文件。用語以專案根目錄的 `CONTEXT.md` 為準，該檔標為「避免使用」的詞，在教材與本文件中都不使用。

驗證腳本只檢查機器能判斷的部分（見「驗證腳本會檢查什麼」）。其餘條文要靠撰寫者與審稿者自行把關，通過驗證不代表符合規範。

## 檔案與 frontmatter

教材一律是 `.mdx` 檔，放在內容根目錄的 `lessons/` 下。正式內容的內容根目錄是 `content/`，所以教材放在 `content/lessons/`；測試與 e2e 用環境變數 `CARLMATH_CONTENT_DIR` 把內容根目錄指到 fixture。選 `.mdx` 而不是 `.md`，是因為教材要內嵌可隨主題切換顏色的 SVG 教具，而且 MDX 出錯時 build 會失敗，不會悄悄發布壞掉的頁面。

每個單元最多一篇教材。單元是否「已撰寫」不另外記錄，由教材檔存不存在推導：新增一個教材檔、`unit` 填上單元 id，該單元頁就從「尚未撰寫」變成閱讀頁。

frontmatter 只有三個欄位，不得新增其他欄位：

```yaml
---
unit: number-line            # 必填，必須是課程地圖上存在的單元 id
description: 一句話摘要。      # 用於單元頁的 description 與 SEO
updated: 2026-10-15          # 最後一次實質修訂的日期，必須是合法日期
---
```

單元的標題、核心問題、階段、建議閱讀順序、先修、親子共學標記（`family`）和課綱附註，全部只寫在課程地圖檔 `content/course-map.yaml`，不在教材裡重寫一份。這是 [ADR 0001：課程地圖是獨立於教材檔的單一來源](adr/0001-course-map-single-source.md) 的決定：大多數單元沒有教材檔，順序與先修若散落在教材 frontmatter，未撰寫的單元就無處存放，也難以檢查先修是否成環。實際的影響是：要改標題或先修，改課程地圖；教材 frontmatter 不放 `title`。

`updated` 只在實質修訂時更新，例如改了推理、換了範例或練習；修錯字、調標點不必更新。首頁的「最近撰寫或更新」卡片依這個欄位排序。

教材用哪一套結構，由課程地圖上該單元的 `family` 決定：`family: true` 寫親子共學篇，`family: false` 寫一般篇。一個單元只會有其中一種教材，不另寫一般篇，也不在一般篇裡穿插親子區塊。

## 一般篇

一般篇的直接讀者是**自學者**，閱讀版面是側欄目錄。

### 九段結構

一般篇固定 9 段，每段用固定的 H2 標題，順序不得調換，標題文字也必須一字不差（驗證腳本逐字比對）。H2 只用於這 9 段，段內需要分層時用 H3 以下。

**1. 情境開場**

用一個生活或工作情境說明這個單元能解決什麼問題，結尾提出本單元的核心問題（AD-5）。核心問題與課程地圖上的 `coreQuestion` 一致。這一段不出現數學符號。

**2. 先修回顧**

適用於有先修的單元；沒有先修的單元，這一段必須改為「暖身」（見「兩種例外」）。放 2–3 題先修單元的提取題，兼作先修檢查，並附先修單元的連結，讓讀者能從卡住的地方回到需要補的單元（RP-4、AD-4）。這些題目是低風險的：不計時、不計分，全站也不使用倒數計時（AD-3）。答案用 `<Answer>` 收合。

這一段放 `<SkipCheck>`，也就是「已經會了？」入口，連到第 7 段「練習」，讓已經熟練的讀者略過直覺、推理與範例（WE-5）。

**3. 直覺**

依「情境 → 圖解 → 符號」三種表徵呈現新概念，並在頁面上標出三者的對應，例如用同一個語意色標出圖上的點與式子裡的數，或在 `<Figure>` 的說明裡寫明哪個對應哪個（CPA-1）。一般篇的具體階段壓縮成一個生活情境或一張教具，不要求實物操作（CPA-5）。教具一律搭配文字說明（CPA-6），同一個概念的主要表徵不超過三種（CPA-3）。本單元的數學符號最早在本段出現，也就是 CPA-1 的三種表徵走到「符號」的時候；在這之前的段落不出現（見「數學式寫法」）。

**4. 推理**

說明為什麼成立，不只給規則（MC-5）。MC-5 原文針對分數與小數單元，要求用數線呈現並說明運算規則為什麼成立；本站把「說明為什麼」推廣成每篇一般篇都有的一段。

**5. 範例**

範例依淡出順序安排：完整範例 → 範例與練習配對 → 留空最後一步 → 留空最後兩步 → 獨立解題（WE-1）。關鍵步驟旁附「為什麼這步成立？」提示，答案用 `<Answer>` 收合（WE-2）。每個解題範例都附「回頭檢查」步驟，例如代回驗算、估算答案是否合理（WE-6）。

至少給兩個表面情境不同的範例，避免讀者只學會一種題型的樣子（WE-3）。較難的題目附多種解法的比較（WE-4）。

**6. 常見迷思**

至少一則常見迷思。每則用 `<Misconception>` 把錯誤範例和正確範例並列，並請讀者指出錯在哪裡、說明為什麼錯，不單獨呈現錯誤範例（MC-3）。每則迷思至少配一題診斷題，題目要設計成持有該迷思的人會答錯（MC-2）。迷思寫在這一段的正文，不放進 frontmatter（MC-1 的例外）。

**7. 練習**

練習只用符號，不再附圖像，因為這是表徵淡出的終點（CPA-2）。約三分之一的題目出自先前單元的題型，而且不標示題目來自哪個單元（RP-2）。新題型要先在本單元單獨練過，才放進交錯題組（RP-3）。先前單元出現過的迷思，其診斷題要在後續單元的交錯練習裡重複出現，不能因為一次答對就算修正了（MC-4）。

練習區開頭註明類似「這裡錯得比較多是正常的，長期記得比較牢」的話（RP-5）。答案與解析一律用 `<Answer>` 收合。

**8. 提取題**

用無提示的提取題取代重點整理（RP-1）。題目要讀者憑記憶作答，不附提示，答案用 `<Answer>` 收合。不要在這一段或其他地方另寫條列式的重點整理。

**9. 下一步**

正文只寫一句銜接的鉤子，單元清單與複習建議由元件產生，規則見「下一步」一節（RP-6）。

### 兩種例外

一般篇的結構只允許兩種例外，其他偏離都要先改規格：

- **沒有先修的單元**：第 2 段的標題必須是「暖身」，不得寫「先修回顧」，內容是 2–3 題生活直覺題，同樣不計時、不計分。反過來，有先修的單元第 2 段必須是「先修回顧」，不得寫「暖身」。是否有先修以課程地圖為準，驗證腳本兩個方向都會檢查。
- **前面沒有足夠單元可交錯**：練習全部出自本單元，不受「約三分之一出自先前單元」的限制。

### 篇幅與題數

正文 2,000–3,500 字，不含解析；練習 6–10 題，提取題 3–5 題。篇幅超出範圍時驗證腳本會提醒，但不擋 build。練習題的難度分級與標示方式尚未決定，留到第一篇一般篇撰寫時再定。

## 親子共學篇

親子共學篇是 `family: true` 單元唯一的教材，同時寫給**家長**與**自學者**。家長讀完後帶**孩子**做親子活動；孩子透過家長安排的活動參與，不是教材的直接讀者。自學者讀到前段階段時，讀「大人先懂」等寫給大人的段落，略過活動即可。閱讀版面是分段步進。

親子篇整體的家長角色是安排時間、陪伴、提問，不要求家長講解解法或代替孩子解題（PC-1）。全篇的寫法都要配合這個角色：給家長能照著做、照著念的材料，而不是要家長先學會再去教。

### 九段結構

親子篇同樣固定 9 段，H2 標題逐字固定、順序不得調換：

**1. 給家長的話**

只放 `<ParentNote />` 元件，不另寫文字。元件產生全站固定的短文，說明家長不需要自己很會數學，並提醒家長不要在孩子面前表達「我數學不好」（PC-8），同時連到「親子共學怎麼用」說明頁。文字放在 `src/lib/parent-note.ts` 的 `PARENT_NOTE` 常數。

**2. 情境開場**

用孩子生活中會遇到的情境開場，結尾提出核心問題（AD-5）。

**3. 開始前**

列出孩子應該已經會的可觀察行為，例如「能一個一個指著數到 10」，讓家長判斷孩子是否準備好了，並附先修單元的連結（AD-4）。「建議先讀」清單由閱讀頁產生，放在這一段，不必手寫。

**4. 大人先懂**

寫給大人的數學，把一般篇的「直覺」與「推理」合併成一段，依具體 → 圖像 → 符號的順序展開（CPA-1），並說明為什麼成立。篇幅 800–1,500 字。

這一段的末尾寫 150–300 字的**自學者延伸**，把本單元的概念往後面的數學延伸，例如一一對應如何用來比較無窮集合的大小、數線最後如何成為實數線。延伸算在 800–1,500 字之內，不另立 H2 或 H3 段落，讓沒有孩子的自學者讀這一段也有收穫。

**5. 常見迷思**

寫孩子常見的迷思，以及它在親子活動中會怎麼表現，讓家長在活動中認得出來。至少一則；錯誤與正確對照時用 `<Misconception>`，並附診斷題（MC-2、MC-3）。

**6. 親子活動**

放 1–3 個 `<Activity>`，至少一個附可列印材料（PC-3、PC-4）。活動的欄位與要求見下一小節。

**7. 練習與解析**

給孩子 4–8 題，難度略高於孩子已經會的程度，不反覆練習已經熟練的內容（PC-6）。每題的 `<Answer>` 解析寫給家長看，內容包括錯誤答案代表孩子怎麼想，以及家長可以怎麼追問。

親子篇的練習不受「只用符號」限制（CPA-2 在親子篇不適用），可以用實物、圖或口頭問答。交錯練習的規定也不同：可以混入先前親子單元的活動或題型，但不強制比例（以此取代 RP-2）。

**8. 隔天再問**

2–3 題提取題，讓家長隔天不給提示地再問一次，答案用 `<Answer>` 收合。

**9. 下一步**

規則與一般篇相同，見「下一步」一節。

### 親子活動 `<Activity>`

每個親子活動都用 `<Activity>` 撰寫，一個活動有七個固定欄位，依序是目的、材料、時間、步驟、家長引導語、卡關時、回饋語範例。其中「時間」寫在 `minutes` prop，其餘六個欄位各用一個 H3 開頭，標題文字、順序都固定：

1. **目的**（H3「目的」）：這個活動要讓孩子掌握什麼。
2. **材料**（H3「材料」）：家中物品或可列印材料。用到可列印材料時，在這一欄連到該材料的列印頁 `/print/<材料 id>/`。
3. **時間**（`minutes` prop）：5–15 分鐘（PC-3）。
4. **步驟**（H3「步驟」）：逐步的「怎麼做」，不寫「多陪孩子算數學」這類泛泛的話（PC-3）。
5. **家長引導語**（H3「家長引導語」）：可以照念的提問句，以提問代替直接糾正（PC-2）。
6. **卡關時**（H3「卡關時」）：孩子常見的卡關點與家長怎麼接。
7. **回饋語範例**（H3「回饋語範例」）：描述策略或努力的回饋語，例如「你換了一個方法試」，避免說「你好聰明」（PC-7）。

props 兩個都必填：`title` 是活動名稱；`minutes` 是字串，寫 5–15 的整數（`"10"`）或用短破折號 `–`（或 `-`）寫的區間（`"5–10"`，前小後大、都在 5–15 內），顯示時一律輸出 `–`。閱讀頁把它畫成金框卡片，表頭放名稱與「約 N 分鐘」，內容是兩欄定義列表（窄螢幕改單欄），欄位內容照 markdown 渲染，所以材料欄的連結、步驟的清單都照常可用。H3 之前不能有內容，六個 H3 也不能多、不能少、不能換順序。撰寫範例：

```mdx
<Activity title="客廳數數" minutes="5–10">

### 目的

體會最後說的那個數，就是一共有幾個。

### 材料

家裡的 7 個小物，或[列印數字卡](/print/number-cards/)。

### 步驟

1. 把小物排成一排。
2. 孩子用手指著，一個一個數。
3. 數完問：「所以一共有幾個？」

### 家長引導語

你剛剛最後數到幾？所以一共有幾個？

### 卡關時

孩子重複指同一個物品：請他把數過的移到旁邊。

### 回饋語範例

你把數過的移開，所以沒有數重複。

</Activity>
```

`<Activity>` 只能放在「親子活動」段，每篇的「親子活動」段放 1–3 個，至少一個的材料欄連到可列印材料。

設計活動時另外遵守下列條文：

- 數數活動要指著實物數，數完問「所以一共有幾個？」，並使用超過 3 的數量（PC-5）。
- 低年級的數感活動附可列印的線性數字盤面（1–10 或 1–100），孩子走格子時要念出數字；盤面必須是直線，不用環形（PC-4）。
- 活動難度略高於孩子現有的程度（PC-6）。
- 盡量沿用前面單元已經準備的材料。例如前三個樣章共用一盒約 30 個小物和數字卡 0–20，家長只準備一次。

### 可列印材料

可列印材料是站內的 SVG 頁面，路徑是 `/print/<材料 id>/`，加上列印用 CSS，不產生 PDF。一份材料一頁，可以給多個單元共用；新單元要用的材料若已存在（例如數字卡 0–20），直接連過去，不另做一份。

新增材料時，要求如下：

- 版面固定 A4 直式，卡片用 mm 定出實際尺寸，剪下來就能用。
- 剪裁線用虛線，卡片不能被切到兩頁。
- 列印時強制淺色，只靠黑線就能使用，家用黑白印表機也印得清楚。
- 螢幕上顯示的站頭、使用說明和「列印」按鈕，列印時全部隱藏。

### 與一般篇的差異與共用

親子篇與一般篇的差異：

- 不使用一般篇的「範例」段，也不得使用 `<SkipCheck>`。
- 「直覺」與「推理」合併成「大人先懂」，具體階段保留實物操作（CPA-5），不壓縮成一張圖。
- 練習不受「只用符號」限制；交錯練習改為可以混入先前親子單元的活動或題型，不強制比例。
- 練習 4–8 題、隔天再問 2–3 題（一般篇是練習 6–10 題、提取題 3–5 題）。
- 全篇約 2,500–4,000 字，不含解析（一般篇是 2,000–3,500 字）。

兩者共用的部分：

- 語氣稱讀者為「你」，其餘語氣與用語規則相同。
- frontmatter 同樣只有 `unit`、`description`、`updated`。
- 數學式、教具與「下一步」的規則相同。
- 驗證腳本依課程地圖的 `family` 決定套用哪一套結構。

另外，課程地圖要求親子共學單元的課綱年級最小值不超過 6，這由課程地圖驗證把關，不是教材本身的規則。單元頁顯示的建議年級由課綱年級的最小值到最大值推導，教材裡不另寫適合幾歲。

## 語氣與用語

稱讀者為「你」，口語但精確，採台灣用語。術語第一次出現時附英文原文，例如「基數原則（cardinality principle）」。標點用全形，引號用「」。

處理焦慮與挫折時，遵守兩條實證條文：

- 不設 growth mindset 宣導單元或段落。回饋文字用一句話把錯誤歸因到策略，例如「換個方法試試」（AD-1）。
- 安撫焦慮的文字一律搭配具體的技能鷹架，例如拆步驟、附提示，不能只給安慰語句（AD-2）。

親子篇給家長的回饋語範例同樣描述策略或努力，不稱讚聰明（PC-7）。

用語遵守 `CONTEXT.md`。撰寫時最容易用錯的幾個詞：

- 讀者稱「自學者」「家長」「孩子」，不用「學生」「使用者」。
- 一個單元的成文內容稱「教材」，不用「文章」「公式表」；一般篇與親子共學篇是教材的兩種結構。
- 單元結尾的無提示題目稱「提取題」，不用「複習題」「重點整理」。
- 讀者容易持有的錯誤想法稱「常見迷思」，不用「易錯點」「陷阱題」。
- 家長帶孩子做的操作稱「親子活動」，不用「遊戲」「作業」。
- 家長列印的用具稱「可列印材料」，不用「講義」「學習單」。
- 全站的單元線性順序稱「建議閱讀順序」，不用「進度」「課表」。
- 單元頁上的年級範圍稱「建議年級」，不用「適用年級」「程度」。
- 課程地圖的第一層稱「階段」，不用「章」「主題」「學習階段」（後者指課綱的年級分段）。

## 數學式寫法

數學式在 build 時由 KaTeX 輸出靜態 HTML 與 MathML，式子寫錯會讓 build 失敗。寫作規則如下。

**符號出現的時機**：本單元的新符號最早在「直覺」段出現，也就是該段依情境 → 圖解 → 符號的順序走到「符號」的時候（CPA-1）；親子篇則最早在「大人先懂」展開到符號時出現。在這之前的情境開場、先修回顧或暖身，不先丟出本單元的新符號。

**新符號附白話讀法**：新符號第一次出現時，附上白話讀法與意思，例如「$a < b$，讀作『a 小於 b』，意思是 a 在數線上位於 b 的左邊」。

**重要式子要有文字說明**：螢幕閱讀器朗讀 MathML 的品質不一，中文語音朗讀數學式尤其沒有保證。所以重要的式子要在正文用文字說明它的意義，不能只放式子。這也符合本站重直覺與推理、不做公式百科的方向。

**行內式與區塊式**：句中的短式用行內式 `$…$`；獨立成行的式子用區塊式，`$$` 上下各占一行：

```mdx
把兩堆合起來，就是

$$
3 + 4 = 7
$$

也就是說，從 3 再往前走 4 步，會停在 7。
```

```` ```math ```` 區塊的輸出與 `$$` 相同，技術上也可以用。過寬的區塊式在手機上會變成水平捲動，不會撐破版面。

**中文要包在 `\text{}` 裡**：數學式裡的中文一律寫成 `\text{…}`，例如 `$3\,\text{公分}$`。直接寫 `$3公分$` 會讓 build 失敗。

**金額的 `$` 要跳脫**：單一個 `$` 就會被當成行內數學式的開頭。要寫美元符號時寫成 `\$`。台灣教材多用「元」，衝突不多，但寫外幣時要記得。

**MDX 元件前後空一行**：`<Figure>`、`<Misconception>`、`<Activity>` 等區塊元件，前後各空一行。元件若緊接在上一段文字的下一行，會被併進同一個段落，產生不合法的巢狀結構：

```mdx
下面這張圖把積木排到數線上。

<Figure>
  ...
</Figure>

注意每一塊積木的右端，正好對齊一個刻度。
```

**SVG 裡不能用 KaTeX**：教具裡的數學標註只能用 SVG 文字。需要真正的公式時，把公式放在 `<Figure>` 的說明裡，或寫在正文。

中文與行內式之間是否加空格，技術上兩種寫法都能正確解析；依據沒有規定，同一篇內保持一致即可。

## MDX 元件

教材只允許使用下列六個元件，以及教具元件的 import。需要新元件時，先改規格與驗證腳本的白名單，不在教材裡自行引入。

- **`<Answer>`**：可展開的答案與解析，預設收合、一題一題翻開，不提供「全部展開」。所有練習、提取題、診斷題與「為什麼這步成立？」提示的答案都放在裡面。摘要文字預設是「看解析」；親子篇的分段步進版面把它畫成「翻開」樣式，用法不變；可選的 `label` prop 用來改摘要文字，例如 `<Answer label="看提示">`，只在摘要需要更貼切的說法時使用。
- **`<Figure>`**：包住教具，負責圖與下方的說明文字。教具元件本身只輸出 `<svg>`，說明寫在 `<Figure>` 裡，只寫「請注意看什麼」。
- **`<Misconception>`**：常見迷思的錯誤範例與正確範例並列，用於「常見迷思」段，以及其他需要錯對對照的地方。子內容用**恰好一條**分隔線 `---` 分成兩半，前半是錯誤範例、後半是正確範例；元件自己加上「錯誤範例」「正確範例」的標籤，內文不必重寫。分隔線與前後內容之間各空一行，否則 `---` 會把上一行變成標題。分隔線必須恰好一條，而且位在 `<Misconception>` 的直接子層，不得巢狀（例如放在引用或清單裡的 `---` 也算違規）；不符時驗證腳本報錯（`lesson-misconception-shape`）：

  ```mdx
  <Misconception>

  看到分母不同，就直接把分子相加。

  ---

  先通分，再把分子相加。

  </Misconception>
  ```
- **`<SkipCheck>`**：「已經會了？」入口，連到第 7 段「練習」。只用於一般篇的第 2 段，親子篇不得使用。
- **`<ParentNote>`**：全站固定的「給家長的話」，並連到「親子共學怎麼用」。自閉合（`<ParentNote />`），沒有 props，只用於親子篇的第 1 段。
- **`<Activity>`**：一個親子活動，含固定的七個欄位（六個 H3 加 `minutes` prop，寫法見「親子活動 `<Activity>`」）。props 是 `title` 與 `minutes`，只用於親子篇的「親子活動」段。

元件的實際外觀由閱讀頁實作決定，撰寫時不需要也不應該在教材裡加樣式。

### 教具的 import 寫法

教材檔裡唯一允許的陳述是教具元件的 import。上面六個 MDX 元件不必 import；教材不得有任何 `export`，也不得 import 教具以外的東西，例如其他元件、資料檔或函式庫。教具的 import 只有兩種合格寫法，一律是預設 import：

- **一次性教具**：從同目錄的 `./<主題>Figure.astro` 匯入。匯入名稱必須以 `Figure` 結尾，而且不能剛好叫 `Figure`，以免和 `<Figure>` 元件撞名。
- **共用教具**：從 `src/components/figures/` 匯入，例如 `NumberLine`、`Counters`。匯入名稱沿用元件原名（PascalCase），路徑是從教材檔出發的相對路徑。

以放在 `content/lessons/` 下的教材為例，合格的寫法如下：

```mdx
import NumberLine from "../../src/components/figures/NumberLine.astro";
import Counters from "../../src/components/figures/Counters.astro";
import BlocksOnLineFigure from "./BlocksOnLineFigure.astro";
```

下列寫法都不合格：`import Figure from "./Figure.astro"`（名稱剛好是 `Figure`）、`import Blocks from "./Blocks.astro"`（名稱沒有以 `Figure` 結尾）、`import { NumberLine } from "..."`（不是預設 import）、`import NL from "../../src/components/figures/NumberLine.astro"`（沒有沿用原名），以及任何 `export const …`。

## 教具

教具是教材中輔助理解的圖解，以原生 SVG 繪製，只作輔助，不取代文字推理。撰寫教材時遵守下列使用規則：

- **一律配文字說明**：每張教具都用 `<Figure>` 包起來，並在正文說明它在表達什麼，不讓圖單獨出現（CPA-6）。每個 `<svg>` 都要有 `<title>` 與 `<desc>`：`title` 是簡短的圖名，`desc` 用完整句子寫出圖中的數值和對應關係，讓不看圖的讀者也能理解。
- **主要表徵不超過三種**：同一個概念的主要表徵不超過三種（CPA-3），例如情境、圖、符號。不要為了同一件事換好幾種圖。
- **數線是主表徵**：數線是從整數、分數、負數一路貫穿到實數與函數的主要表徵（CPA-4）。能用數線表達的概念，優先用數線，並使用共用的 `NumberLine` 元件，讓數線在全路線長得一樣；小物圓點用共用的 `Counters` 元件。其他教具做成一次性的 `<主題>Figure.astro`，和該單元的教材放在一起。
- **顏色只用色票 token**：教具裡的顏色屬性（例如 `fill`、`stroke`）只允許 `currentColor`、`none`、`transparent`、`inherit` 或 `var(--…)`，而且 `var()` 不得帶 fallback 色碼，例如 `var(--accent, #2563eb)` 不合格。hex、色名（如 `red`）、`rgb()`、`hsl()` 都不允許。每個 token 都有全站固定的語意，顏色也不能是唯一的訊息來源。

教具的繪製規範，包括 `viewBox`、字級、線寬、色票 token 的語意、文字標籤數量、`NumberLine` 與 `Counters` 的參數，以及什麼時候要拆成兩張圖，見 `docs/figure-guide.md`（由教具共用元件票建立）。單一版面與封閉色盤的理由見 [ADR 0002：教具採單一版面與封閉色盤](adr/0002-figures-single-layout-closed-palette.md)。本文件不重述這些細則。

## 下一步

每篇教材的最後一段是「下一步」，告訴讀者接下來讀什麼、怎麼複習。單元清單由課程地圖推導，依下面三種情況決定：

1. **下一個單元依賴本單元**：預告建議閱讀順序上的下一個單元。
2. **下一個單元不依賴本單元**：依建議閱讀順序列出全部反向依賴，也就是所有以本單元為直接先修的單元，讓讀者知道本單元會在哪些後續單元用上。
3. **沒有任何單元以本單元為先修**：只預告下一個單元。

單元清單由「下一步」元件從課程地圖取得，正文不手寫清單。正文只寫一句鉤子，而且只寫給清單中最近的那個單元，也就是建議閱讀順序上排最前面的那一個。第 1、3 種情況下就是下一個單元；第 2 種情況下即使元件列出多個單元，鉤子也只寫給最近的一個。

以「數線」為例：下一個單元「湊十」不依賴數線，所以屬於第 2 種情況。元件依建議閱讀順序列出估算與四捨五入、分數在數線上、角、負數，正文的鉤子只寫給估算與四捨五入。

複習建議是全站固定的文字，由閱讀頁接在「下一步」段之後（文字在 `src/lib/review-advice.ts`），建議讀者隔一天、一週、一個月，各回來做一次本篇的提取題，先不看解析（RP-6）。網站不記錄學習進度，所以複習建議只以文字呈現，教材裡不另寫。

前後單元的銜接點要寫在正文裡，而不是只靠「下一步」的清單。例如三篇樣章的銜接：數數的一一對應是「物和數詞配對」，到比多少延伸成「物和物配對」；比多少的「多幾個」是沒配到的數量，到數線變成兩點之間的距離。

## 驗證腳本會檢查什麼

`pnpm validate:content` 執行內容驗證，把違規分成錯誤和提醒兩級印出；有錯誤時以非零狀態結束，擋下 build。教材相關的自動檢查如下：

| 類別 | 檢查項目 | 等級 |
| --- | --- | --- |
| frontmatter | `unit` 必填且存在於課程地圖；`updated` 是合法日期；不得有 `unit`、`description`、`updated` 以外的欄位；每個單元至多一篇教材 | 錯誤 |
| 結構 | 依單元的 `family` 檢查 9 個固定 H2 齊全且依序 | 錯誤 |
| 暖身 | 一般篇在課程地圖上沒有先修的單元，第 2 段必須是「暖身」；有先修的單元，第 2 段必須是「先修回顧」，不得是「暖身」 | 錯誤 |
| 元件 | 只允許 `<Answer>`、`<Figure>`、`<Misconception>`、`<SkipCheck>`、`<ParentNote>`、`<Activity>` 與教具元件；import 只接受預設 import 的同目錄 `./<主題>Figure.astro`（名稱以 `Figure` 結尾且不是 `Figure`），或 `src/components/figures/` 下以原名匯入的共用教具（相對路徑）；不得有 `export`，也不得 import 其他東西 | 錯誤 |

| 親子活動結構 | 每個 `<Activity>` 都有非空的 `title`，`minutes` 是 5–15 的整數字串或「a–b」區間，子內容依序是「目的、材料、步驟、家長引導語、卡關時、回饋語範例」六個 H3（不得多、少、換順序，H3 之前不得有內容，也不得有其他標題）；`<Activity>` 只能出現在親子篇的「親子活動」段（`lesson-activity-shape`） | 錯誤 |

| 迷思對照 | 每個 `<Misconception>` 的子內容恰有一條直接子層的分隔線（`---`）分開錯誤範例與正確範例，0 條、2 條以上或巢狀的都報錯 | 錯誤 |

同一個指令也會檢查課程地圖本身，例如 id 不重複、先修存在且排在前面、親子共學單元的課綱年級最小值不超過 6；這些屬於課程地圖的維護，不是撰寫教材時的規則。數學式錯誤則由 build 本身擋下，不經過這個指令。

其餘條文都需要人工把關，包括但不限於：各段的內容是否符合本文件的要求、題數、範例的淡出順序、三種表徵的對應、交錯練習的比例、迷思是否附診斷題、`<Activity>` 各欄的內容是否寫得具體、連到的可列印材料是否真的存在、「大人先懂」與自學者延伸的字數、語氣與用語、新符號是否附讀法，以及「下一步」的鉤子是否寫給最近的單元。教具的 `desc` 是否真的寫出數值與對應關係，也只能靠人看。
