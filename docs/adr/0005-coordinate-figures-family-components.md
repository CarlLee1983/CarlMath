# 坐標與函數圖形分成三個專用元件，函數以「族＋係數」宣告

從坐標平面到積分，七個階段都要畫坐標軸與曲線。這些圖拆成三個共用元件，各自帶固定的版式：`CoordPlane` 畫點、線段與坐標平面上的圖形，x、y 等比例並畫整數淡格線，讓讀者能從圖上讀出坐標；`FunctionGraph` 畫函數曲線、切線、頂點與漸近線；`AreaGraph` 畫曲線下或兩曲線之間的塗色，以及黎曼和的長條。後兩個元件只畫軸和軸上的短刻度，不畫格線，y 軸可以和 x 軸不同比例，讓陡的曲線也能撐滿寬 480。函數不以任意的 JS 函式傳入，而是宣告它屬於哪一族、係數是多少（例如 `{ quadratic: [1, -2, -3] }`）。頂點、對稱軸、切線斜率和長條高度都由元件計算，build 因此能像 `Shape` 驗證度數那樣，驗證圖上標的數字。主角曲線用 `--fg` 主線，`--accent` 只用在讀者該注意的東西上，例如切線、頂點、塗色區與被標記的點。`Shape` 維持 ADR 0003 的決定，不畫軸，相似三角形與畢氏定理這類不需要坐標的圖留在 `Shape`。

考慮過的替代有兩個，2026-10-16 用拋棄式原型（分支 `prototype/coord-graph`）並排比較過。第一個是只做一個通用的 `Plot`，所有東西都是圖層，而且永遠等比例畫方格紙；這會讓參數表很長，y 範圍大的圖（切線、黎曼和）也會縮到只剩約 200 寬。第二個是擴充 `Shape`，加上 `axes` 與 `curves`；這樣黎曼和的長條得由作者逐一手寫頂點，而且會推翻 ADR 0003。若改用 JS 函式，什麼曲線都畫得出來，但 build 不知道曲線屬於哪一族，頂點和斜率得由作者手算，也無法驗證。這個選擇的代價是每多一族函數（指數、對數、三角……）就要擴充元件，族的實作跟著各階段逐步加。

**Falsified if:** 某個階段需要畫的曲線無法表示成任何一族加係數，必須在 `docs/figure-guide.md` 為函數圖形開放任意函式；或為了畫坐標平面上的形狀，必須讓 `src/lib/shape-geometry.ts` 畫出座標軸，而不是改用 `CoordPlane`；或 `FunctionGraph` 必須支援方格紙與等比例，才能讓讀者從圖上讀出函數值。
